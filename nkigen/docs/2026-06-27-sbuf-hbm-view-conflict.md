# Bug: SBUF-to-HBM view conflict after annotate-memory-space deletion

**Date:** 2026-06-27
**Status:** Open
**Affects:** head_deconcat, qwen3_layer, and any kernel that returns a
reshaped view of an SBUF intermediate

## 1. The Pattern

```python
x = np.reshape(input, (2, 128, 2, 128))
x = np.transpose(x, (0, 2, 1, 3))
x = np.reshape(x, (256, 256))
knob.knob(x).tile_op(...).layout(mem_space="SharedHbm")
result = x @ w
return result
```

User intent: compute the 4D transpose in SBUF, then use the result
(reshaped to 2D) as an HBM tensor for the downstream matmul.

## 2. IR After Tiling (before canonicalize-reshape)

```mlir
%alloc = memref.alloc() : memref<2x128x2x128xf32>
nkipy.layout(%alloc) {mem_space = Sbuf}              // infer-layout put this

%view = memref.reinterpret_cast %alloc to [256, 256]
nkipy.layout(%view) {mem_space = SharedHbm}          // user's knob
```

The frontend uses `memref.reinterpret_cast` for all reshapes (zero-cost
view, no data movement). No `collapse_shape` or `expand_shape` is
generated by the frontend — only by later passes (simplify-linalg,
legalize-layout) for SBUF physical layout reasons.

## 3. Where It Fails

`canonicalize-reshape` runs `applyMemSpaceAnnotations` which:
1. Stamps `%alloc` type → `#nkipy.mem<Sbuf>`
2. Stamps `%view` type → `#nkipy.mem<SharedHbm>`

The MLIR verifier then rejects: `reinterpret_cast` source and result
have different memory spaces.

## 4. The Fix

In `applyMemSpaceAnnotations` (canonicalize-reshape prologue): after
applying all layout annotations, detect view ops where source and
result ended up with different mem_spaces. For each conflict:

1. Create `%hbm_alloc = memref.alloc() : memref<result_shape, SharedHbm>`
2. Insert `memref.copy %view, %hbm_alloc`
3. Replace all uses of `%view` (except the copy) with `%hbm_alloc`

This materializes the SBUF→HBM transition that the user's annotation
implies. The view stays valid (source and result both Sbuf), and a
separate HBM buffer holds the copied data.

## 5. Design Notes

- The frontend deliberately avoids `collapse_shape` / `expand_shape`.
  All user reshapes are `reinterpret_cast` (contiguous, row-major).
- `collapse_shape` / `expand_shape` appear only in later passes
  (simplify-linalg, legalize-layout) for SBUF physical tiling.
- The conflict only arises when a view crosses a mem_space boundary.
  Same-space views (SBUF→SBUF, HBM→HBM) are fine and common.
